# P2Flux documentation

Developer documentation for integrating P2Flux — programmable, non-custodial payments on Base.

**The guides live at [p2flux.com/docs](https://p2flux.com/docs/).** This repository holds the two
things that belong in version control: the machine-readable API contract, and the description of the
on-chain layer.

## What P2Flux is

Payments move **buyer wallet → recipient wallet**, with the P2Flux fee split out in the same
transaction. There is no custody, no balances and no accounts: P2Flux never holds funds and never
becomes an intermediary that could.

Recurring payments work the same way. The customer signs an EIP-712 authorization once with an
ordinary EVM wallet, on terms they can read — amount, period, recipient, an end date. After that a
merchant's own system triggers each renewal, and the contract enforces one charge per period against
the terms that were signed. P2Flux has no scheduler and no database; **your application owns the
subscription lifecycle**, P2Flux executes the payment when you say so.

Refunds follow from the same model: a refund is a plain USDC transfer from the merchant's own wallet
back to the wallet that paid. P2Flux verifies it and never performs it — no refund contract, no
custody, no new fee.

## What P2Flux stores about you

Nothing that identifies anyone. Customers, orders, products, prices and subscription records stay in
your database; P2Flux handles only the protocol information a payment needs. The payment reference is
random and generated by P2Flux, so an order id or an email address cannot end up inside it by
accident — you keep your own `order → reference` mapping.

## Environments

| | API | Hosted checkout | Chain |
|---|---|---|---|
| Test | `api-test.p2flux.com` | `pay-test.p2flux.com` | Base Sepolia (84532) |
| Production | `api.p2flux.com` | `pay.p2flux.com` | Base Mainnet (8453) |

The two are complete, non-interchangeable stacks — a capability issued by one is refused by the
other, by construction. **Integrate against the test environment.** Production exists and is
**pre-launch: not open yet, which is not an outage**. Live state is on the
[status page](https://p2flux.com/status.html).

## SDKs

| | |
|---|---|
| [sdk-js](https://github.com/P2Flux/sdk-js) | JavaScript/TypeScript, dependency-free |
| [sdk-php](https://github.com/P2Flux/sdk-php) | PHP 8.1+, injectable transport |
| [contracts](https://github.com/P2Flux/contracts) | Solidity sources, ABIs, EIP-712 definitions, chain constants |

Neither SDK is published to npm or Packagist yet — install from a pinned git tag. The two do not yet
cover the same surface: `createSubscription`, `createPayment`, `verifyPayment` and
`createCancellationSession` exist in PHP only. The [API reference](https://p2flux.com/docs/api/)
describes the HTTP endpoints themselves, which both can reach.
